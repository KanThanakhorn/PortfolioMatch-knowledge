> **อัปเดตใหม่ 1 พ.ย. 2569 หลัง Supabase:** รายการเลขหน้าด้านล่างตรวจจาก PDF เดิมและเป็นประวัติการแก้รอบก่อน. ข้อความที่ว่า “ไม่มี database/authentication/ข้อมูลข้ามเครื่อง” ไม่ใช่สถานะปัจจุบัน. ให้ใช้ [nut-supabase-update-2026-11-01.md](nut-supabase-update-2026-11-01.md) และ [report-draft.md](report-draft.md) เป็นแหล่งหลักก่อนแก้ PDF/สไลด์; แล้วใช้เลขหน้าในรายการนี้หาตำแหน่งเดิม.

ตรวจไฟล์ `Report_PortfolioMatch.pdf` (12 หน้า, สร้าง 31 ต.ค. 2569) และ `สีแดง สีเหลือง scrapbook ตัดแปะ กระดาษ โครงงาน งานนำเสนอ Presentation.pdf` (13 สไลด์, สร้าง 1 พ.ย. 2569) เทียบ requirement อาจารย์และโค้ด `kan/backend` วันที่ 1 พ.ย. 2569. **ไฟล์ PDF ต้นฉบับไม่ได้ถูกแก้**; ใช้รายการนี้แก้ไฟล์ Word/Canva แล้ว export ใหม่.

## ปรับคุณภาพก่อนนำเสนอ

- รายงานมีหัวข้อหลักครบ 10 ข้อตาม requirement แต่ literature ยังเป็นเอกสารแนวทางกว้าง ๆ 3 แหล่ง; เพิ่มงานวิจัยเฉพาะเรื่องถ้าหาแหล่งที่ตรวจสอบได้ และตรวจรูปแบบบรรณานุกรม.
- สไลด์ 8–9 แสดงเครื่องหมายถูกแต่ไม่มีวันทดสอบ/สภาพแวดล้อม/ภาพหลักฐาน; เพิ่ม footer อ้างรายงาน QA พร้อมระบุรอบทดสอบ.
- สไลด์ 10 ระบุ `Pass บางส่วน` ตามสถานะเก่า; อย่าเปลี่ยนเป็น Pass เต็มจนตง retest ทั้งหน้า.
- สไลด์ 11 future work ควรเป็น database, file storage, authentication, rate limit, audit log และการประเมิน AI; ไม่ควรเขียนว่า “เริ่มเชื่อม AI” เพราะทำแล้ว.
- เพิ่มสไลด์สั้นเรื่อง Literature Review กับทรัพยากร/ต้นทุน หากเวลาในการนำเสนอพอ; อย่างน้อยให้ผู้พูดเตรียมคำตอบจากรายงาน.
- ทดสอบ Demo บนเบราว์เซอร์เดียวกันและใช้ PDF จำลองที่ไม่มีข้อมูลส่วนบุคคล. หากสาธิต Gemini สด ให้รอผลหรือมีภาพสำรองเมื่อ API หนาแน่น. อย่าแสดง API key.

## ข้อความสั้นที่นำไปแทนในรายงาน

> ระบบต้นแบบ PortfolioMatch ใช้ Next.js Route Handler ส่ง Portfolio PDF ไปยัง Gemini API เฉพาะเมื่อผู้สมัครให้ความยินยอม AI ส่งกลับคะแนนเสนอแนะ สรุป และหลักฐานตามเกณฑ์เพื่อให้กรรมการตรวจประกอบการตัดสินใจ ผลทดสอบ endpoint ด้วย PDF จำลองสำเร็จแล้ว แต่การแสดงผลผ่านหน้าเว็บและการทดสอบ responsive ทุกส่วนยังต้องยืนยันซ้ำด้วยหลักฐานจาก Frontend QA ข้อมูลใบสมัครและผล AI เก็บเฉพาะใน localStorage ของเบราว์เซอร์เดียว ส่วน PDF ต้นฉบับไม่ได้เก็บไว้ในระบบ

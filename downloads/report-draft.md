# PortfolioMatch: ต้นแบบระบบช่วยจัดการและคัดกรองใบสมัคร Portfolio

> ร่างสำหรับนัทปรับเป็นรายงานฉบับส่งตาม requirement ของอาจารย์ (สถานะโค้ด 31 ตุลาคม 2569, branch `kan/backend`). โปรดตรวจชื่อสมาชิก ระยะเวลา ต้นทุน และผล QA หลังแก้ก่อนส่ง. ภาพหน้าจอและแผนภาพอยู่ใน `assets/`.

## 1. ชื่อโครงการ (Project Title)

PortfolioMatch: ต้นแบบระบบช่วยจัดการและคัดกรองใบสมัคร Portfolio
ภาษาอังกฤษ: *PortfolioMatch: An Interactive Prototype for Portfolio Admission Screening*

## 2. ที่มาและความสำคัญ (Background and Motivation)

การรับสมัครรอบ Portfolio มีข้อมูลส่วนตัว ผลงาน และเกณฑ์พิจารณาหลายส่วน กรรมการต้องเปิดเอกสารและเปรียบเทียบผู้สมัครด้วยตนเอง ทีมจึงออกแบบหน้าจอรวมข้อมูลและแสดงสถานะการพิจารณาในที่เดียว เพื่อลดขั้นตอนสลับเอกสารและช่วยให้การพิจารณาอ้างอิงเกณฑ์เดียวกัน ต้นแบบนี้แสดงแนวคิด AI ช่วยสรุปและมนุษย์ตัดสินใจ แต่ยังไม่มีการวิเคราะห์ด้วย AI จริง จึงยังไม่ควรอ้างว่าลดเวลาหรือเพิ่มความแม่นยำโดยไม่มีผลวัด.

## 3. วัตถุประสงค์ (Project Objectives)

1. สร้างต้นแบบ flow ตั้งแต่กำหนดรอบรับสมัครจนถึงการตัดสินใจของกรรมการ.
2. รวมข้อมูลผู้สมัคร สถานะ และคะแนนตัวอย่างให้เห็นจากหน้าจอเดียวกัน.
3. ตรวจรูปแบบข้อมูลสำคัญก่อนบันทึกใบสมัครสาธิต.
4. สื่อสารข้อจำกัดและความเสี่ยงของการใช้ AI ในงานรับสมัครอย่างตรงไปตรงมา.

## 4. กลุ่มเป้าหมาย (Target Users)

- **อาจารย์/กรรมการรับสมัคร:** ต้องการเห็นรายชื่อ ข้อมูล และสถานะในมุมมองเดียว ใช้ข้อมูลประกอบการตัดสินใจ และตรวจหลักฐานต้นฉบับก่อนอนุมัติ.
- **นักเรียน/นักศึกษาผู้สมัคร:** ต้องการทราบเกณฑ์ของรอบสมัคร กรอกข้อมูล เลือก PDF และรับคำยืนยันว่าข้อมูลเดโมถูกบันทึกในเบราว์เซอร์.

## 5. ขอบเขตของระบบ (System Scope)

**Core features ที่มีในต้นแบบ:** ตั้งค่ารอบตัวอย่าง, แบบฟอร์มและการตรวจข้อมูล, บันทึกข้อมูลผู้สมัครใน localStorage, ค้นหาชื่อ/โรงเรียน, ดูรายละเอียด, Approve/Reject และ dashboard ที่นับจากข้อมูลชุดเดียวกัน.

**Optional / Future work:** ฐานข้อมูลและบัญชีผู้ใช้, รับไฟล์ PDF จริง, วิเคราะห์ด้วย AI, หลายรอบรับสมัคร, Filter/Sort, audit log และการทดสอบกับผู้ใช้จริง.

ภาพประกอบ: `assets/scope-map.svg`

## 6. การทบทวนวรรณกรรม (Literature Review)

- NIST (2023), *Artificial Intelligence Risk Management Framework 1.0*: ใช้กรอบคิดในการระบุความเสี่ยง ความน่าเชื่อถือ และอคติของ AI ก่อนใช้งานจริง. DOI: https://doi.org/10.6028/NIST.AI.100-1
- UNESCO (2023), *Guidance for Generative AI in Education and Research*: สนับสนุนการคงบทบาทมนุษย์และการใช้ AI อย่างระมัดระวังในบริบทการศึกษา. https://www.unesco.org/en/articles/guidance-generative-ai-education-and-research
- W3C (2024), *Web Content Accessibility Guidelines 2.2*: ใช้อ้างอิงการออกแบบฟอร์ม โดยเฉพาะการระบุข้อผิดพลาดและป้ายชื่อช่องกรอก (SC 3.3.1, 3.3.2). https://www.w3.org/TR/WCAG22/

แหล่งเหล่านี้เป็นพื้นฐานสำหรับการออกแบบและการประเมินความเสี่ยง ไม่ใช่หลักฐานว่า PortfolioMatch มีประสิทธิภาพสูงขึ้นแล้ว. ตรวจรูปแบบบรรณานุกรมตามที่อาจารย์กำหนดก่อนส่ง.

## 7. วิธีดำเนินงานและสถาปัตยกรรม (Methodology and Architecture)

กำหนดผู้ใช้และ User Flow → ออกแบบหน้าจอและข้อมูลตัวอย่าง → พัฒนาด้วย Next.js App Router, React, TypeScript, CSS และ Lucide → ทดสอบ flow ในเบราว์เซอร์. React Client Components จัดการ form และ interaction. localStorage เก็บ campaign กับผู้สมัครในเบราว์เซอร์เดียวกัน; sessionStorage จำหน้าสำเร็จในแท็บเดิม. ยังไม่มี backend API, database, authentication, file storage หรือ AI service.

ภาพประกอบ: `assets/user-flow.svg`, `assets/system-architecture.svg`

## 8. ผลการดำเนินงาน (Project Results)

ต้นแบบมี Dashboard, Applicants, Applicant Detail, Create Admission, Application Form และหน้าสำเร็จหลังส่งใบสมัคร. ข้อมูลเริ่มต้นมีผู้สมัครตัวอย่าง 4 คน คะแนน 92, 86, 74 และ 61; ค่าเฉลี่ยปัดเป็นจำนวนเต็ม 78%. ตัวเลขเป็นข้อมูล mock. รูปหน้าจอใน `assets/dashboard.png`, `create-admission.png`, `application-form.png`, `applicants.png`, `applicant-detail.png` ถ่ายจาก production build ณ 31 ต.ค. 2569.

ทีมแบ่งงานเป็นกานต์ (flow/integration), ตง (QA/demo stability), นัท (รายงาน/สไลด์/UX). ทรัพยากรที่ยืนยันจาก repo คือ Next.js, React, TypeScript, CSS และ Lucide. **ข้อมูลชั่วโมงทำงาน ค่าอุปกรณ์ และค่าใช้บริการยังไม่ได้ยืนยัน** ให้เติมจากข้อมูลจริงของทีมก่อนวิเคราะห์ต้นทุน–ประโยชน์. ประโยชน์ที่คาดหวังคือการรวมข้อมูลเพื่อช่วยการพิจารณา; ยังไม่มีผลวัดเชิงปริมาณ.

## 9. การประเมินผลและการทดสอบ (Evaluation and Testing)

รายงาน QA ของตงลงวันที่ 30 ต.ค. 2569 เป็น baseline ก่อนแก้หลัง merge. ผลล่าสุดของกานต์: `npm run typecheck` และ `npm run build` ผ่าน; ทดสอบสร้างลิงก์, บล็อกการส่งเมื่อไม่มี PDF, ส่งฟอร์มพร้อมไฟล์ `.pdf` ทดสอบ, รีเฟรชหน้าสำเร็จ, รายชื่อใหม่ปรากฏ และ Approve เปลี่ยนตัวเลข dashboard. การส่งไฟล์ในเดโมบันทึกเฉพาะชื่อ ไม่ใช่เนื้อไฟล์.

**รอทดสอบซ้ำพร้อมภาพหลักฐาน:** Reject หลังรีเฟรช, ไฟล์ผิดชนิด/เกิน 50 MB, และทุกส่วนของหน้ามือถือ. ให้นำผล Pass/Fail ใหม่ของตงมาเติมก่อนส่งรายงาน.

## 10. สรุป ข้อจำกัด และ Future Work

PortfolioMatch แสดง flow การรับสมัคร Portfolio และการพิจารณาผู้สมัครในรูปแบบ interactive prototype ได้ โดย Dashboard รายชื่อ และรายละเอียดใช้ข้อมูลชุดเดียวกันภายในเบราว์เซอร์. ยังสรุปไม่ได้ว่าระบบลดเวลาในการตรวจหรือเพิ่มความถูกต้อง เพราะยังไม่มีการวัดกับผู้ใช้จริง.

ข้อจำกัด: ข้อมูลไม่ซิงก์ข้ามเครื่อง, ไม่เก็บเนื้อไฟล์ PDF, ไม่มี AI วิเคราะห์จริง, ไม่มีสิทธิ์ผู้ใช้ และยังมีกรณี QA ที่ต้องทดสอบซ้ำ. งานต่อไปคือ backend/database/file storage, ระบบสิทธิ์และ audit log, ทดลอง AI พร้อมกรรมการตรวจผล และทดสอบ usability/performance กับผู้ใช้จริง.
